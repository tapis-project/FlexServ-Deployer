# FlexServ 1.5 Alpha native Slurm bundle

The ZIP is extracted by Tapis into an existing Slurm job directory. Start
`app/run_flexserv.sh`; `--control-plane-only` skips inference environment setup.
The entry accepts `--enable-https` and `--trust-remote-code` in any order.
`PRI_MODEL_REPO` and `PUB_MODEL_REPO` remain environment variables, passed unchanged
to Gateway and the generated FCS host request. Remote-code selection only exports
`FLEXSERV_TRUST_REMOTE_CODE=true` (otherwise `false`); backend behavior is unchanged.
There are only two executable products. The architecture suffixes `amd64` and
`arm64` mean `linux-x86_64` and `linux-aarch64` respectively. The bundle contains
both, so compute nodes do not download another binary or compile Rust.

## Call sequence

`run_flexserv.sh` enters the first allocated node, selects one site, sources
function definitions and `flexserv.env`, then calls installation, site access
preparation, launch, tunnel setup, access-info publication, and foreground wait.
`launch-flexserv.sh` keeps Gateway and one `srun` step as owned background jobs.
Every node runs one Capability Server; rank zero has `head` and `worker`, others
have `worker`. An EXIT trap stops owned jobs and releases site ports. No restart,
external PID adoption, database, container or model download is involved.
The entry resolves the job directory to its physical path before generating
private runtime files, including when launched through a directory alias.

## Environment and permissions

Set `FLEXSERV_SITE=tacc|osc|template` or allow FQDN/cluster detection. Set
`HOST_TYPE` if the compute hostname does not identify the machine. Partition is
read from the job. `HARDWARE_ENV` defaults to `${HOST_TYPE}-${SLURM_JOB_PARTITION}`;
it is a directory/profile label, not proof of accelerator capability.

`FLEXSERV_VENV_ROOT` defaults to `/work/projects/aci/cic/apps/flexserv/virt_envs`
for Vista/Stampede3, `/opt/share/virt_envs` for DGX, and
`$HOME/tapis-app/flexserv/virt_envs` elsewhere. Override an unwritable default;
there is no sudo or ownership repair. Runtime roots must also be canonical, owned
by the service account, and not group/world writable. Shared site defaults that
fail this policy require an explicit private-root override before installation. Python lives in `python/$HARDWARE_ENV`,
vLLM/aiperf in `vllm-venv-$HARDWARE_ENV`, MAX in
`modular-max-$HARDWARE_ENV/.venv`. Existing valid environments are reused.

Set `VLLM_VERSION`, `AIPERF_VERSION`, `MAX_VERSION` for exact versions. Otherwise
missing packages resolve stable compatible versions and record them. Backend
facts are inspected before installation; set `FLEXSERV_ACCELERATOR_BACKEND` when
site detection is unavailable. XPU/ROCm additionally require an approved
`FLEXSERV_VLLM_INDEX`. No CUDA fallback or automatic source build is attempted.
MAX defaults to `auto`; unsupported platforms are reported as skipped, while an
installation failure on a supported platform remains an error. Set
`FLEXSERV_INSTALL_MAX=1` to require it, or `0` to disable it. MAX is environment
preparation only in this release, not a serving adapter.

Shared environments use `flock`. The lightweight script runtime needs Bash,
jq, Slurm tools, SHA-256/unzip/zipinfo utilities and standard Linux commands; backend installation
also needs network access and curl or wget. MAX has its own linker and hardware
requirements. The control plane itself requires no C/C++/protobuf tools.

For deployment calls provide Slurm-approved device IDs through inherited
visibility settings or `FLEXSERV_GPU_DEVICES`. `FLEXSERV_SERVICE_PORT_START/END`
default to 18000/18100. Set `FLEXSERV_SERVICE_BIND` only for an approved concrete
node address. To preapprove inference publication, set `FLEXSERV_MODEL_ID` to the
exact model ID; this does not deploy it. Optional `FCS_VLLM_API_KEY` is kept out
of policy files. The private policies and poll digests are generated by the
actual native FCS binary for the merged Pack, without PyYAML/source checkouts.
Tapis/SSH resources are not automatically granted; those tools can be discovered
but require separately configured credentials/authorization for execution.

## Transport and access

Gateway prepares runtime/rank config, FCS holds its actual listener, and Gateway
issues the existing job-scoped mTLS identities. Temporary keys are staged only
in `tmp/tls/<run-id>`; all-role load acknowledgements and initial authenticated
discovery precede removal of `tmp/tls`. Persistent manifest/status are under
`runtime/<run-id>`. A missing peer, invalid identity, expired job, startup timeout
or cleanup error prevents ready publication. Restart recovery is unsupported.

TACC defaults to public HTTP. `--enable-https` requires TAP certificate/key files
and enables only the public Gateway HTTPS listener. The script optionally sources
`/share/doc/slurm/tap_functions` (override `TAP_FUNCTIONS`). When unavailable it
generates a cryptographically random token and uses its Bash `get_login_port`
logic to select a candidate not observed listening on reachable login nodes.
Actual SSH forwarding must still acquire that port. TAP token/port facilities
are used when present. The script opens foreground SSH processes to configured
`FLEXSERV_LOGIN_NODES` (default login1..4). Site SSH configuration must permit
the requested reverse forwarding (`GatewayPorts clientspecified` for the default
public remote bind). Both HTTP and HTTPS request a public reverse bind by default.
Set `FLEXSERV_TUNNEL_BIND=127.0.0.1` for a laptop-only SSH forwarding setup.
Override `FLEXSERV_TUNNEL_BIND` or `FLEXSERV_PUBLIC_HOST` for
site policy and public DNS; the default public host resolves the configured login
SSH alias, never the compute node. At least one tunnel must stay alive through
setup. Public HTTPS selection and internal mTLS identity are separate: the
Gateway/FCS transport always verifies both job identities and remains encrypted
in public HTTP mode. No plaintext fallback exists on the internal channel.

OSC uses `https://$OSC_ONDEMAND_HOST/rnode/<compute-host>/<port>/` (host defaults
to ondemand.osc.edu), without SSH or Apptainer. Set
`FLEXSERV_TRUSTED_PROXY_NETWORKS` to the approved OOD proxy CIDRs. This explicit
peer restriction is required for the HTTP leg after OOD's HTTPS termination;
forwarded headers alone are not trusted. Browser MCP clients also require
explicit Gateway Origin authorization; non-browser clients send the accepted
Host authority. Generic sites default to internal access and manual SSH forwarding.

Credentials are written only to the private `flexserv_access_info.txt` (0600),
with `FlexServ token: ` retained for existing scanners. Logs print the URL and
file location. Administrator and backend credentials are distinct from public
access. Keep the job's access-info file private when archiving/sharing logs.

## Published versus runtime files

Published: `app/`, `scripts/`, four `bin/*.bin`, one `pack/*.zip`, `BUILD.json`,
`checksums.sha256`, and `tapisjob.manifest`. Runtime: `runtime/pack`, per-run
`config/manifest/status`, `logs/`, `reports/` and private access-info. Venvs remain
outside the job directory and are not deleted on exit. TLS staging is removed.

GitHub Actions resolves component release tags once to exact IDs and commits,
downloads their verified binaries and two Packs, and publishes `Tapis-FlexServ.zip`
plus checksum. Native components are built and ABI-checked in their own
repositories; Deployer never compiles them. See [component releases](COMPONENT_RELEASES.md).
It does not embed
mistral.rs, build a GPU variant, or install an optional engine. The checksum
checks integrity, not publisher authenticity by itself.

Pushing `feature/1.5.0-alpha` assembles published component releases and refreshes
the fixed Alpha 44 download URL only after integrity and Pack checks pass. The
workflow creates no Deployer tag or new release. The Alpha 44 Git tag remains
at its original commit; BUILD.json and run-specific Actions artifacts identify
current bytes. To build without publishing, run the workflow manually with
`publish_release` disabled. Explicit component tags select reproducible inputs.
Published Beta detection freezes Alpha updates. See the component release guide
for source branches, credential boundaries and 90-day artifact retention.

## Private source repositories

Set the Deployer Actions secret `FLEXSERV_SOURCE_TOKEN` to a credential with read
access to releases in the three selected private component repositories. An existing
`FCS_ARTIFACT_READ_TOKEN` is also accepted when it has all three grants. The
default GITHUB_TOKEN cannot read unrelated private repositories. Cross-owner
private reusable-workflow sharing is not required: Deployer downloads release
assets without checking out component source or calling component workflows.
Gateway downloads come from tapis-project/FlexServ, not the personal fork.
Never put the token in source,
BUILD metadata, a Tapis environment file, or a chat message.

## Tapis application parameters

The Alpha ZIP entry starts the control plane without positional arguments. Use
its environment configuration (or `--control-plane-only` for manual testing).
The existing `tapis_def/1.4.0` examples still describe the old 1.4 release and
retain its arguments; do not point that App at the Alpha ZIP without removing
retired model/device/quantization arguments. This delivery does not create or
change live Tapis Apps, Systems or Jobs.

The [1.5.0 TACC App definition](../tapis_def/1.5.0/app.json) and
[registration/job preparation guide](../tapis_def/1.5.0/README.md) describe the new
entry. Runtime `.sh` files contain Bash orchestration only: JSON uses checked-in
jq filters, package installation uses uv CLIs, and package smoke tests invoke
their normal CLI entrypoints. Python programs remain limited to build/test code
and the actual inference runtime, not shell configuration helpers.
